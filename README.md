# ⚡ OneByte Agent

### مساعد Android ذكي — Neon Intelligence. Electric Tools. Your Device, Your Control.

**من تصميم سليمان**

**OneByte Agent** مساعد ووكيل ذكاء اصطناعي لنظام Android بواجهة Neon، يجمع الشات والصوت والذاكرة والمهارات والمهام وأدوات الويب والتحكم الاختياري بالهاتف، مع Cybersecurity Lab يتضمن استطلاعًا آليًا للنطاقات المصرح بها، مكتبة أدوات Hunting دائمة، وتوليد أدوات Python محلية قابلة للاختبار وإعادة الاستخدام. يدعم مزوّدي API المتوافقين مع OpenAI، ويضع موافقات واضحة قبل الإجراءات الحساسة. البيانات المحلية تُحفظ على الجهاز، بينما تُرسل الطلبات إلى مزوّد النموذج الذي تختاره عند استخدامه.

## ⚡ فكرة المشروع

**OneByte Agent** تطبيق Android مبني باستخدام **Expo SDK 57** و **React Native 0.86** و **React 19** و **TypeScript 6**. بدل ما يكون مجرد شات، فهو يشغّل حلقة وكيل (Agent Loop) تستطيع فيها النماذج المتوافقة مع واجهة OpenAI أن تطلب أدوات محددة، وينفّذ التطبيق الأدوات وفقًا لقواعد الموافقة والصلاحية.

هو مشروع **Local-first**: بيانات المحادثات والمهارات والذاكرة تُدار محليًا على الجهاز، لكن هذا لا يعني أن كل البيانات تبقى على الهاتف دائمًا؛ نصوص المحادثات التي ترسلها إلى الموديل تذهب إلى مزوّد الذكاء الاصطناعي الذي تختاره، وأدوات الويب والتكاملات الخارجية تتصل بخدماتها عند استخدامها.

### 🌩️ الهوية البصرية: Electric Spiderweb

الرسم الموجود أعلى الصفحة هو عنصر الهوية الأساسي للمشروع: شبكة كهربائية حول نواة مركزية، ومسارات مضيئة مستوحاة من **Neon Cyan / Electric Blue / Lightning Red**. الفكرة البصرية تعكس ارتباط أجزاء التطبيق ببعضها:

- ⚡ **Model** — الموديل الذي يفهم الطلب ويقترح الخطوات.
- 🔌 **Tools** — الأدوات التي تنفّذ عمليات محددة.
- 🧠 **Memory** — سياق محلي يساعد على الاحتفاظ بالمعلومات المهمة.
- 🛡️ **Approval** — طبقة تحكّم للموافقة على إجراءات الهاتف الحساسة.

## ✨ المزايا

### 💬 الشات والذكاء الاصطناعي

- بث مباشر للردود (Streaming) من مزوّدي النماذج المتوافقين مع OpenAI Chat Completions.
- حلقة أدوات: يمكن للموديل طلب أداة، انتظار النتيجة، ثم متابعة الرد.
- إعداد عنوان API واسم الموديل والمفتاح، مع قوالب لمزوّدين متعددين ودعم نقاط النهاية المتوافقة.
- فحص اتصال الموديل ومساعدة في فهم أخطاء HTTP الشائعة مثل `401` و`404` و`429`.
- دعم إرفاق الصور والملفات في مسار الشات، بحسب نوع الملف والموديل المستخدم وقدرات المزوّد.
- إيقاف الطلب الجاري من واجهة الشات، بما في ذلك انتظار الموديل والمهام التي تدعم الإلغاء.
- دعم الرسائل التي تحتوي على نصوص متعددة الأسطر وصور متعددة، مع محاولة التعامل مع الطلبات الطويلة عبر تقسيم النص أو تلخيصه داخليًا عند الحاجة. يظل التنفيذ محدودًا بسياق الموديل وحدود المزوّد.
- واجهة شات مُحسّنة: رأس مضغوط، سجل محادثات في الدرج الجانبي، فقاعة مستخدم بعرض مناسب للنص، وإجراءات للنسخ والتعديل، مع إجراءات أيقونية لرسائل المساعد.

### 🧠 الذاكرة والمهارات والسياق

- حفظ معلومات مختارة في ذاكرة محلية يمكن للأدوات الرجوع إليها.
- حفظ المهارات وقراءة التعليمات الكاملة لمهارة عند الحاجة.
- بحث في المحادثات المحفوظة، بما في ذلك المحتوى الذي لم يعد ظاهرًا بالكامل في سياق الموديل.
- تلخيص أجزاء من سياق المحادثة للمساعدة في التعامل مع المحادثات الطويلة.
- مهام يومية وتذكيرات محلية يمكنها فتح الطلب المرتبط بها داخل الشات.

### 📱 أدوات الهاتف — عند تفعيلها فقط

يمكن لخدمة Android الأصلية استخدام Accessibility لتنفيذ عمليات مسموحة داخل الهاتف، مثل:

- قراءة عناصر واجهة الشاشة الحالية.
- فتح تطبيق أو رابط.
- الضغط على عنصر، وكتابة نص في حقل عادي، والتمرير.
- تنفيذ بعض مفاتيح النظام والانتظار حتى تستقر الشاشة.
- عرض طلبات الموافقة قبل استخدام أدوات قراءة الجهاز أو التأثير عليه.

التحكم في الهاتف **اختياري**، ويتطلب تثبيت نسخة Android مبنية مع الوحدة الأصلية ثم تفعيل خدمة إمكانية الوصول من إعدادات النظام. هذه الوظائف لا تعمل بالكامل داخل Expo Go.

### 🌐 أدوات الويب والمتصفح المدمج

- البحث في الويب باستخدام DuckDuckGo وجلب محتوى صفحة عامة عندما يطلب المستخدم ذلك.
- في نسخة Android، يستطيع الوكيل توجيه WebView المدمج لفتح رابط مصرح به، وقراءة عنوان الصفحة ونصها والعناصر التفاعلية، والنقر والكتابة في الحقول غير الحساسة، والتمرير والانتظار.
- يمكنه إرسال طلبات HTTP محددة من سياق الصفحة وتحليل status/headers/الجسم وزمن الاستجابة، ثم استخدام نتيجة الأداة لمتابعة الاستدلال.
- لوحة **حركة الشبكة** تلتقط داخل النطاق المصرّح به طلبات JavaScript من نوع `fetch` و`XHR` و`sendBeacon` والتنقلات الرئيسية، مع الحالة والمدة ومعاينة الاستجابة وحجب بيانات الاعتماد الشائعة. يمكن نقل الطلب الملتقط إلى محرّر HTTP في Cybersecurity Lab لتعديله ثم إرساله يدويًا بعد التحقق من النطاق.
- هذا الالتقاط ليس Proxy كاملًا ولا يضمن تسجيل كل الصور والملفات الثابتة وWebSocket أو طلبات Service Worker. إعادة الطلب من سياق الصفحة تظل خاضعة لـCORS؛ استخدم HTTP Lab في Android عند الحاجة إلى طلب مباشر.

### 🧩 عرض المحتوى

- عرض Markdown بعناوين وقوائم بدل عرضه كنص خام.
- تنسيق كتل الكود مع إمكانية نسخها، ودعم تنزيل كتل الكود كملف عند توفر الإجراء في الواجهة.
- عرض مخططات Mermaid، مع مراعاة ألوان `classDef` و`class` و`:::` الموجودة في المصدر.
- معاينة Mermaid بمحرك Mermaid الأصلي في العرض المدعوم داخل التطبيق/الويب.
- معاينة HTML داخل WebView مع إمكانية إعادة التحميل أو فتحها في المتصفح عند توفرها.
- دعم الثيم الفاتح والداكن والتلقائي.

### 💻 واجهة الكمبيوتر المصاحبة

يمكن تشغيل خادم PC من إعدادات التطبيق ثم فتح عنوانه من متصفح كمبيوتر على **نفس شبكة Wi-Fi**. تفتح الواجهة المصاحبة بتخطيط كمبيوتر مستقل، ويمكن تخصيص الثيم واللون من إعداداتها أو مزامنتها مع إعداد الهاتف. يسجّل المستخدم الدخول باستخدام PIN، وتظل موافقات إجراءات الهاتف الحساسة مرتبطة بالجهاز.

> استخدم هذه الواجهة على شبكة موثوقة فقط. الخادم المحلي ليس بديلًا عن نشر خدمة آمنة على الإنترنت، ولا ينبغي فتح منفذه للعامة أو تحويله مباشرة إلى عنوان عام.

### 🛠️ مساحات عمل متخصصة

- **Developer Lab:** مساحة لتجارب وتحرير المحتوى البرمجي وبعض أدوات المعاينة.
- **Marketing Studio:** مركز سريع لفتح حسابات YouTube Studio وTikTok وFacebook وInstagram وWhatsApp Web/Desktop وTelegram Web، مع فتح مساعد التسويق لكتابة المحتوى وخطط الحملات.
- **Cybersecurity Lab / Bug Hunter:** مساحة مستقلة عن محادثات المطوّر والتسويق، مع أقسام للنطاق والاستطلاع وHTTP والنتائج. إدارة نطاقات الاختبار، وتحرير طلب HTTP (GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS)، وتعديل headers/body، وإرسال الطلب أو إلغاؤه، وقراءة status/الوقت/مقتطف الاستجابة، والرجوع إلى سجل الطلبات.
- **Autonomous Hunting Engine:** يبدأ من نطاق محفوظ ومصدر تصريح يضيفه المستخدم، ثم يفتح الهدف في المتصفح المدمج ويجمع DOM والنص ومصدر الصفحة بعد تنقيح مؤشرات الأسرار، ويقرأ سجلات fetch/XHR/sendBeacon التي يلتقطها المتصفح.
- **Recon pipeline:** استخراج روابط وAPI path candidates وملفات JavaScript من الصفحة وحركة الشبكة، ثم جمع أسماء النطاقات الفرعية بشكل سلبي من Certificate Transparency عبر crt.sh. لا يتم إرسال طلبات إلى النطاقات الفرعية المكتشفة تلقائيًا.
- **Adaptive Hunting Planner:** يرسل الأدلة المحدودة إلى موديل OneByte المحدد لبناء خطة تالية. إذا اقترح الموديل قدرة غير متوفرة، يستطيع توليد كود Python وحفظه كمسودة في المكتبة؛ لا يتم تشغيل المسودة تلقائيًا.
- **Hunter Tool Registry:** مكتبة محلية دائمة منفصلة عن المحادثات، تحفظ ID واسم الأداة ووصفها ومخطط مدخلاتها ومخرجاتها والكود وإصداراته وحالة الاختبار وآخر استخدام. يستطيع Agent عرض المكتبة وإعادة استخدام الأدوات المعتمدة أو حفظ أدوات جديدة دون تكرار الاسم.
- **Python Runtime:** يشغّل أدوات Python على الجهاز داخل Pyodide WebAssembly Worker منفصل داخل WebView. لكل تشغيل Worker وذاكرة ملفات افتراضية مؤقتة، ولا يحصل كود Python على Native Bridge أو شبكة مباشرة. يوجد حد للكود والمخرجات ووقت التنفيذ، مع إنهاء Worker عند انتهاء المهلة.
- **اعتماد الأدوات:** الأداة الجديدة تبدأ Draft؛ يفتح المستخدم مصدر الإصدار ويؤكد أنه راجعه، ثم يشغّل اختبارًا يدويًا لعقد run(args)، وبعد نجاحه يعتمد الإصدار صراحةً قبل أن يصبح Verified ويستطيع Agent تشغيله. أي تعديل ينشئ إصدارًا جديدًا ويلغي إقرار المراجعة السابق. تحديث الكود ينشئ إصدارًا جديدًا ويعيده إلى Draft.
- **سجل Hunting:** يحفظ الهدف والخطة وملخص الصفحة والروابط والنطاقات الفرعية والطلبات المرصودة وملاحظات الموديل محليًا، منفصلًا عن رسائل الشات.
- **اختبار ويب من المتصفح المدمج:**
  - فتح URL داخل WebView المدمج (يتطلب نطاقًا محفوظًا في Cybersecurity Lab).
  - قراءة الصفحة: عنوان، نص، عناصر تفاعلية مفهرسة.
  - التفاعل: نقرة، كتابة، تمرير، انتظار.
  - تحليل حركة الشبكة: طلبات `fetch`/`XHR`/`sendBeacon` الملتقطة داخل النطاق.
  - إرسال طلبات HTTP مخصصة (GET/POST/PUT/PATCH/DELETE/HEAD/OPTIONS) مع headers/body معدّلة، وقراءة الاستجابة.
  - توثيق الأدلة: لقطات صفحة، استجابات، طلبات مرسلة.

## 🚀 التثبيت والتشغيل

### المتطلبات
- Node.js ≥ 20
- pnpm ≥ 9 (أو npm/yarn)
- Expo CLI: `pnpm add -g expo-cli`
- Android Studio + SDK (للبناء الأصلي)
- Git

### خطوات سريعة
```bash
# استنساخ المستودع
git clone https://github.com/elssoliman86-codesoli/onebyte-agent.git
cd onebyte-agent

# تثبيت التبعيات
pnpm install

# تشغيل خادم التطوير (Expo)
pnpm expo start

# بناء APK للاختبار المحلي (يتطلب EAS CLI)
pnpm add -g eas-cli
eas build --platform android --profile preview
```

### تشغيل على جهاز/محاكي
1. افتح `expo start` واضغط `a` لفتح محاكي Android، أو امسح الكود بـ Expo Go.
2. للنسخة الكاملة مع أدوات الهاتف: ثبّت APK المبني عبر EAS، ثم فعّل **خدمة إمكانية الوصول (Accessibility)** من إعدادات النظام > إمكانية الوصول > OneByte Agent.

## ⚙️ الإعداد الأول

1. **الموديل ومفتاح API:** الإعدادات > الموديل > أدخل `API Base URL` و `Model Name` و `API Key`. يدعم قوالب لمزوّدين متعددين (OpenAI، OpenRouter، Ollama، LM Studio، إلخ).
2. **فحص الاتصال:** اضغط "فحص الاتصال" للتأكد من صحة الإعدادات.
3. **الثيم:** اختر فاتح/داكن/تلقائي من الإعدادات > المظهر.
4. **PC Server (اختياري):** فعّله من الإعدادات > PC Server، ثم افتح العنوان الظاهر من متصفح كمبيوتر على نفس الشبكة.
5. **المهارات:** فعّل المهارات المدمجة أو ثبّت مهارات جديدة من سوق المهارات.

## 🛠️ الأدوات والأوامر

| الأداة | الوصف | تتطلب موافقة؟ |
|---------|---------|----------------|
| `web_search` | بحث DuckDuckGo | لا |
| `web_fetch` | قراءة صفحة ويب عامة | لا |
| `open_url` | فتح رابط في WebView مدمج | لا |

## 🔒 الخصوصية والأمان

- **محليًا أولاً:** المحادثات، المهارات، الذاكرة، المهام — مخزنة في `AsyncStorage`/`MMKV` على الجهاز.
- **الموديل:** نصوص المحادثات المرسلة للموديل تذهب إلى مزوّد API الذي تختاره. لا نملك وصولًا لها.
- **أدوات الويب:** `web_search`/`web_fetch` تذهب إلى DuckDuckGo والموقع المستهدف مباشرة.
- **المتصفح المدمج:** يعمل داخل WebView على الجهاز؛ الكوكيز وتخزين الموقع قد يستمران للجلسات التي تفتحها. يتم تنقيح نص الصفحة وsource snapshot وسجلات الشبكة قبل حفظ/تمرير مقتطفات منها قدر الإمكان، وتُمنع تنقلات الإطار الرئيسي خارج النطاق النشط.
- **Certificate Transparency:** استعلام أسماء النطاقات الفرعية يرسل اسم النطاق إلى خدمة crt.sh ويستقبل سجلات عامة؛ لا يرسل طلبات إلى النطاقات الفرعية المكتشفة.
- **لا جمع بيانات:** لا يوجد تتبع، تحليلات، أو إرسال بيانات لمخدومات المشروع.
- **الترخيص:** MIT — راجع [LICENSE](./LICENSE).

## ⚠️ القيود المعروفة

- أدوات الهاتف (Accessibility) لا تعمل في Expo Go؛ تحتاج بناء APK مخصص وتفعيل الخدمة يدويًا.
- React Compiler في وضع تجريبي (beta)؛ قد تظهر مشاكل مع مكتبات معينة.
- `browser_send_request` خاضع لـ CORS وسياسات المتصفح؛ للطلبات المباشرة استخدم HTTP Lab.
- Pyodide 0.29.5 يتم تحميل ملفاته أول مرة من jsDelivr؛ تشغيل Python نفسه محلي على الجهاز، لكن لا يوجد ضمان أن Runtime سيعمل Offline قبل تحميله أو بعد مسح WebView cache. ملفات Runtime ليست مضمنة داخل APK حاليًا.
- بيئة Python تدعم المكتبات القياسية المتاحة في Pyodide فقط؛ لا توفر Raw Sockets أو وصولًا حرًا للشبكة أو Native Extensions غير المبنية لـ WebAssembly.
- حدود الوقت وحجم الكود والمخرجات لا تعادل حدًا صارمًا للذاكرة أو عزلًا أمنيًا مطلقًا؛ لا تشغّل كودًا غير موثوق، ولا تعتمد أداة مولدة قبل مراجعتها واختبارها.
- التقاط حركة الشبكة ليس Proxy كاملًا؛ لا يسجل كل الموارد الثابتة أو WebSocket.
- PC Server مخصص للشبكة المحلية الموثوقة فقط؛ لا تفتحه للإنترنت العام.
